# 姿势识别优化实施与验证

实施日期：2026-10-09。本报告记录 v1.7.2 的姿势识别变更；发布以注释 tag 的 CI 结果及线上资产校验为准。

发布已完成：源码 c737cef，tag 守门与四端构建全绿，[v1.7.2](https://github.com/cwxa/HealthyDesk/releases/tag/v1.7.2) 于北京时间 11:07 发布为 Latest。8 项资产匿名下载响应及大小正确，7 项产物线上 SHA256 与清单一致，APK 下载字节再次校验通过。云端界面测试 308 项通过、2 个移动端假摄像头片段因低帧率未验证；本机生产构建 352 项通过。

## 已交付行为

1. **测量使用真实画面比例。** 双端提取生产几何函数，按像素横纵比例计算头部侧倾、肩部高度差及躯干侧倾。桌面传输保持宽高比，最长边 640；骨架按实际画面尺寸叠加。可信的 40° 侧倾保留，不再因超过旧上限变成 0°。
2. **缺失部位不会冒充健康。** 每项独立返回 valid/confidence/reason，拒绝非有限值、低可见度、出框和退化几何。头肩可测而髋部不可测时返回 partial_pose：显示可测值，暂不计算总分、不写坐姿采样；运动仅使用当前动作所需的有效指标，禁止默认 0 补值。角度界面使用“躯干”表述。
3. **会话与结果有明确生命周期。** 模式变化先清平滑状态；异步启动支持取消，重复绑定只保留一个推理循环，停用/卸载清理监听与定时器。无新结果超过 1.5 秒使旧分数失效，冻结视频不会重复发布旧帧。停止及连接关闭同步通知页面失效，旧连接回调不能影响新连接。
4. **平滑按时间更新。** 以原 5fps/alpha=0.35 对应的时间常数更新 EMA；大间隔、乱序时间或模式改变重置状态；缺失指标从缓存删除。本地目标间隔 100ms，隐藏页面暂停推理。
5. **推理不会占住后端事件循环。** 初始化、解码、推理、释放由同一有序工作线程执行。一个摄像头会话拥有跟踪器，前端最多一个在途帧；使用 session_id/frame_id/captured_at 匹配结果，超时重连，发送失败清理在途状态。模型 ready 后才开始发送视频。
6. **显示与保存遵循测量语义。** 实时运动徽章来自当前动作的质量判定，部分可测的头部动作也能显示判定；没有有效判定时显示未判定，不借其他部位的偏离生成分数。
7. **新旧数据保留且分开统计。** 新测量 metric_version=2；SQLite 迁移 6 和 IndexedDB schema 3 保留旧记录为 v1，日归档使用日期/测量版本联合主键。当前统计只聚合 v2，旧记录继续保留在历史/备份中。SQLite 重建在 SAVEPOINT 内执行，失败整体回滚，可重试。
8. **备份不会丢失联合主键。** 新导出格式为 v2，仍接受旧 v1 备份，缺测量版本时赋值 1。旧客户端会拒绝新版文件，避免忽略版本字段后覆盖同日归档。CSV 增加测量版本列。

核心变更位于 src/platform/poseGeometry.ts、poseSmoother.ts、localPoseEngine.ts，backend/services/pose_geometry.py、pose_session.py、smoother.py，以及 hooks、摄像头 WebSocket 和数据维护模块。

## 验证与复现

| 命令 | 验证内容 |
| --- | --- |
| `npm run build:web` | TypeScript 编译和 Vite 生产构建 |
| `npm run verify:all` | 双端评分/平滑/几何/动作/聚合/导出/UTC、数据库迁移、业务守卫、配置及两代素材回归 |
| `npm run verify:pose` | 14 个跨语言几何输入、4 种比例和镜像的独立理论值、5/15/30fps 时间响应、模式切换、部分测量、真实引擎及 hook 生命周期/连接竞态 |
| `npm run verify:ui` | 真实 Chrome 中 15 项 IndexedDB 升级/保留/分版本/旧备份/往返恢复检查，以及 5 种平台配置、3 个路由、352 项界面断言；Android/iOS 配置包含模型假摄像头链路 |
| `.buildenv/Scripts/python.exe scripts/verify-pose-runtime.py` | 真实 aiosqlite 归档与注入失败后的迁移回滚；后台 100ms 推理时并发心跳；会话独占、坏帧应答、释放；6 张素材的真实 MediaPipe 推理 |
| `.buildenv/Scripts/python.exe scripts/fake-camera/build-pose-v2.py` | 重建 v2 素材与登记结果，每个 1.5/2/3/5fps 档位独立运行模型跟踪及时间 EMA |

v2 素材由既有测试图整帧旋转生成，采用 3 帧起势及持续强信号，评分阈值未放宽。四档真实 Python 推理登记均为 completed；CI 直接运行当前 TS 判定函数核对四档录制序列。旧 7 案例保留为历史动作算法回归，其静止被判 insufficient 的已登记偏差仍如实标识。

运行时报告写入忽略的 `.buildenv/pose-runtime-report.json`。多轮六图采样的单图平均推理耗时约 31–75ms，包括与浏览器测试并行运行的负载；仅代表本机小样本。空场景 no_pose，其余半身素材 partial_pose，髋部不可见不生成躯干总分。没有以该测试声称真人准确率或性能提升百分比。

Windows 沙箱内 Python asyncio 的本机 socketpair 初始化出现阻塞；相关回归及 Chrome 本机服务使用获批的沙箱外执行。测试使用内存数据库、新建临时浏览器配置和项目测试素材，不改用户运行中的数据库。

## 后续范围

- 当前统计升级后只显示 v2，旧统计可由历史和备份访问；不得将旧指标伪重算为新版。
