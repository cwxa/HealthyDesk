# 核心姿势识别审查与更新计划

审查日期：2026-10-08；当前项目版本：1.7.2。
范围：Python 推理、浏览器本地推理、坐姿评分、运动评分、平滑、摄像头传输、结果入库及现有验证脚本。

2026-10-09 实施更新：测量正确性、部分测量协议、生命周期、时间平滑、传输背压、有序后台推理与数据版本隔离已完成开发。验证方法和交付边界见 [实施报告](POSE_RECOGNITION_IMPLEMENTATION.md)。以下问题与链路描述保留为修改前的审查快照；阶段 B 的负载自适应/持续时间滞回，以及阶段 C 的方向特征/个人校准仍为后续工作。

## 1. 当前链路与能力边界

- 桌面端：NeckActivity 每 200ms 将画面绘制为 640×480 JPEG → WebSocket Base64 → OpenCV 解码/缩放 → Python MediaPipe Solutions Pose → 三项二维指标 → EMA → scorer → 展示/静息采样入库。
- 本地端：usePoseEngine 的 rAF/timeupdate → Tasks Vision PoseLandmarker（GPU 优先、CPU 回退）→ 三项二维指标 → EMA → scoringModel → 展示/本地入库。
- 三项指标实际为耳线侧倾、肩部高度差、肩髋中线相对竖直方向的侧倾。最后一项并非脊柱曲度；当前输入不能直接证实圆肩、头前伸或驼背。应先校正 UI/报告用语，再评估新增侧面机位或其他观测量。
- 两端公式接近不代表同一画面最终同分：模型/API、输入缩放、实际帧率和跟踪状态不同。应分别验证“同一关键点输入的计算一致性”和“同一视频的推理差异”。

## 3. 分阶段交付

### 阶段 A：先让测量可信（预计 3–5 个工作日）

1. 提取两端真实几何函数，输入包括 landmarks、原始尺寸及输入变换；桌面缩放改为等比例裁剪/填充，保存映射。
2. 增加按项质量协议：valid、confidence、reason；reason 至少区分 no_person、low_visibility、out_of_frame、degenerate_geometry、inference_error。验证 finite/presence（接口可用时）及框内性。
3. 支持部分可测结果。总分在关键指标缺失时显示“测量不完整”；如果提供上半身分数，需单独命名和版本化，避免当作三项完整总分。联动 types、scorer、统计、导出及入库验证，禁止以默认 0 补缺失。
4. 修复 mode 重置顺序、异步启动竞态、重复循环、监听清理、会话平滑状态和过期结果。
5. 增加 scoring_version/metric_version 与完整性标记。先保持旧数据可读，新旧统计明确分段；没有原始关键点/视频的历史记录不伪造重算。

验收：宽高比解析用例与理论值一致；髋部不可见不生成躯干健康结论；异常几何不产生良好分；模式切换首帧与新建平滑器相同；连续启停/重试后仅一个调度循环，旧会话结果不入库。

### 阶段 B：稳定实时链路（预计 3–5 个工作日）

1. 引入时间 EMA、有效结果 TTL、丢失/恢复状态和持续时间滞回，避免单帧报警；阈值在回放集上选择，不预设为已验证参数。
2. 本地推理按目标 FPS 调度，具备页面隐藏暂停和负载自适应；依据基准结果决定 Worker 迁移，保留 GPU/CPU 回退。
3. 后端将解码/推理移出事件循环，采用有序执行和最新帧策略；前端限制在途帧，使用帧标识测端到端延迟。二进制传输按实测收益决定，不先做大范围协议重写。
4. 统一摄像头帧尺寸、画面变换、显示骨架和推理坐标；用 4:3、16:9、竖屏及镜像叠加验证。

验收：低性能设备持续运行无无界积压；模拟断流能使旧分数失效；5/15/30fps 输入得到接近的时间响应；HTTP/设置请求在推理负载下保持可响应。

### 阶段 C：提升动作和个人适配（预计 5–8 个工作日）

1. 统一实时与收尾动作质量计算，按动作采用带方向指标、相对基线、保持和循环状态；明确无法观察的动作，避免仅凭幅度称“动作正确”。
2. 在修正后的指标上设计 10–20 秒中立坐姿校准：稳定样本中位数、波动估计、质量门槛和重新校准提示；摄像头倾斜需先纠正或拒绝校准，不能把工位/不良姿态全部吸收成正常基线。
3. 与 ROADMAP 的个人基线需求合并，避免再维护另一套阈值；保存 baseline_version 和 camera profile，切换机位使旧校准失效。
4. 另立侧面观测探索任务，用标注视频评估头前伸等新增指标的可观测性；已有二维侧倾指标不改名冒充新能力。

验收：静止歪坐、不相关部位移动、左右反向动作不获得目标动作完成结论；实时/收尾口径一致；校准可重复、可失效且拒绝不可靠输入。

工期为单开发者的初步估算，包含开发和回归；真人样本收集、标注与多设备实测需额外安排，不能用该估算承诺识别准确率。

## 4. 验证与观测

- 保留现有跨语言评分/聚合/导出测试，但将角度测试改为执行真实生产函数。
- 新增独立解析基准：真实像素倾角、不同尺寸、镜像、缺髋、耳肩重合、NaN、极端倾斜、转头、离开/恢复、模式切换及生命周期竞态。
- 增加同视频双模型推理比较；既有假摄像头回放主要验证登记指标到动作判定，不能证明两套模型的准确率或推理性能。
- 真人评估按参与者拆分校准/验证集，覆盖眼镜、遮挡、暗光、多人、不同体型、机位和桌面半身画面；人工标注依据固定规则，报告误差、可测覆盖率、漏报/误报及每小时误提醒次数。
- 性能记录 decode_ms、infer_ms、score_ms、end_to_end_ms 的 P50/P95，以及 FPS、dropped_frames、queue_depth、推理失败、恢复时间和内存趋势。移动端额外记录 UI 卡顿和持续运行发热表现。
- 日志：入口/出口记录会话创建、初始化、停止和释放；关键分支记录 delegate 回退、模式切换、失去/恢复姿态、过期/丢弃帧及异常。上下文包含 sessionId/frameId、输入尺寸、mode、质量、耗时和错误栈。正常逐帧路径使用采样/聚合 debug，避免高频 info 抵消性能优化；不记录图像或 Base64。
- 新版本先并行计算旧/新指标做回放比较，确认差异原因；版本开关用于回滚，同一统计窗口禁止混合不同评分语义。

## 5. 本次检查的验证结果

实际运行了 npm run verify:parity 和 node scripts/fake-camera/replay.mjs。已完成的评分、平滑、角度、部位聚合、运动完成度、日聚合及导出验证均通过；parity 最后一项时间戳验证停留在 Python 探针阶段，交付时尚未返回，因此不能宣称整个 parity 已通过。现有角度用例只覆盖 8 条公式等价案例，不包含宽高比正确性、髋部置信度、模式切换首帧和异步启停。

假摄像头 7 个案例均与登记结果一致，其中 still-person-12s 仍为已登记语义偏差：静止被判 insufficient 而非 idle。登记一致是回归依据，不是准确性证明。未运行真实摄像头、全模型视频比较或移动真机性能测试，因此本计划不报告未经测量的准确率或性能提升比例。

建议首个更新集中交付阶段 A；完成后再推进性能和个人适配，避免把错误指标算得更快。
