## 使用与判定

先摆正摄像头，自然坐直，让头、肩、髋部入镜，再点“开始校准”。目标窗口为连续 10 秒，至少 30 个独立样本；整个尝试最多 20 秒。半身缺髋、未检测到人、运动模式、测量旧版本或低质量帧不进入窗口。任一原始绝对指标超过既有通用提醒线时重新开始窗口，避免把明显歪坐吸收成中立位。

三项置信度至少 0.8；窗口内有效帧间隔最多 600ms；采样最多 10Hz。低帧率需要更长时间满足样本下限；不足约 2fps 的链路难以完成校准。重复回包不增加样本、不刷新保持时间。使用未经过分数 EMA 的带方向测量，减少平滑掩盖波动的影响。

基线中心取中位数。离散程度取 MAD（相对中位数的绝对偏差中位数），并检查 P90-P10 范围。头/肩/躯干的 MAD 上限为 0.6°/0.8%/0.8°，范围上限为 2°/2.5%/3°。这些是工程质量门槛，尚无真人临床标定；没有据此声称诊断能力或准确率提升。

校准采集期间暂停姿态入库和新增姿态语音。模式变化、摄像头变化、停止、页面隐藏或卸载都会退出采集；无回包也有独立超时。取消重新校准保留原基线，成功且保存完成才替换。保存失败明确提示失败。

## 方向、评分和数据

TS 和 Python 的生产测量都增加 `signed_metrics`，质量契约与原绝对指标一致。头部/肩部方向来自原始画面的线斜率，躯干方向来自肩髋中点连线；镜像令方向反转，绝对幅度保持一致。界面中的正负只表示原始画面方向，不映射为人体左右动作结论。

显示的个人变化为当前带方向值减去基线中位数。缺失或低质量测量立即隐藏相对变化，不沿用旧值。既有健康评分、提醒阈值、运动幅度、日统计及 `issues 非空 ⇔ score < 80` 契约保持原口径；基线不用于自动提高分数，也不用于认定拉伸动作正确。

配置使用本机 `localStorage` 独立键 `neckguardian.posture-baseline.v1`，包含 `baseline_version=1`、`metric_version=2`、设备/方向/分辨率 profile、画面比例、采集时间、样本数、中心及 MAD。无设备或尺寸信息时禁用采集。机位 profile 变化或超过 30 天使配置失效；损坏、未知版本、越界中心/离散度也会被拒绝。

机位绑定数据不进入跨设备健康备份，防止恢复备份后误用另一摄像头的中立位。健康数据清除不修改此配置，个人基线通过页面“重置基线”单独删除。仅靠人体二维关键点无法可靠判断实体摄像头是否在同一设备、同一规格下移动或倾斜，因此此类变化仍需用户重新校准，不能声称自动检测全部机位变化。

## 验证与后续

- `npm run verify:pose`：双端绝对与带方向测量、镜像、四种画面比例、原评分生命周期及校准生产模块回归。
- `npm run verify:calibration`：39 项生产算法检查及 20 项真实 Chrome 中的 React/DOM/localStorage 交互检查，包括保存失败、取消保留原基线、机位变化、隐藏、无帧超时及卸载。
- `npm run verify:all` 和 `npm run verify:ui`：原业务回归和五种平台配置的界面测试；两组校准检查分别接入既有 CI 的 parity 与 UI 命令。

本阶段对应 ROADMAP 需求 6 的采集与个人参考部分。阈值自学习、宽松/标准/严格灵敏度、真人评估及活动左右方向判定仍为后续范围，不将整个需求 6 标为完成。原先“基线随设置备份迁移”的提案调整为本机机位专属保存；以后如增加迁移，必须在恢复后重新验证机位，而不能直接激活旧基线。
